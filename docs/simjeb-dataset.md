SimJEB takes the entries to the [GE jet engine bracket challenge](ge-jet-engine-bracket.md)
and cleans, orients, meshes and simulates them under the challenge's four load
cases. Every design has the same bolt holes, the same pin interface, the same
load vectors and the same material. That makes SimJEB the only public place where
the challenge's boundary conditions are written down as an actual solver deck.

Sections 1–5 record what the dataset contains, as the paper, the README and our
own look at the sample files report it. Section 6 is this project's reading of
how the dataset could be used here.

## 2. Simulation setup (read from the sample deck `148.fem`)

The table below turns the challenge's prose into solver terms. Every figure comes
straight from the OptiStruct cards.

| Aspect | SimJEB model |
| --- | --- |
| Solver | Altair OptiStruct, deck generated by HyperMesh 2020.0; linear static; four subcases sharing one SPC set |
| Units | mm, N, MPa (N/mm²), tonne/mm³ |
| Frame | **+z is vertical up** and the base sits at z ≈ 4.24 mm. Pin centre (the load node) is at (−21.04, −75.06, 44.80) mm in design 148 |
| Material | `MAT1` Ti-6Al-4V: E = 113,800 MPa, ν = 0.342, ρ = 4.43×10⁻⁹ t/mm³. No yield value is in the deck |
| Elements | **First-order `CTETRA` (4-node)**, average size 2.0 mm, minimum 0.6 mm, growth rate 2.0, tet-collapse threshold 0.1. Design 148 has 640,197 tets and 129,260 nodes |
| Bolt interfaces 2–5 | One **RBE2** rigid spider per bolt hole, tying every node on the hole surface to a centre node. That centre node is fixed in all six DOF (`SPC 123456`) |
| Pin interface 1 | One **RBE3** distributing spider from the load node to the nodes on the pin-bore surface. Loads go on the RBE3 reference node |
| LC1 `vertical` | `FORCE` (0, 0, **+35,585.77**) N |
| LC2 `horizontal` | `FORCE` (**−37,809.9**, 0, 0) N. "Out" is **−x** in this frame |
| LC3 `diagonal` | `FORCE` (**−28,276.2**, 0, **+31,403.9**) N. Magnitude 42,258.1 N; **42.00° from vertical**, tilted toward "out" |
| LC4 `torsion` | `MOMENT` (0, 0, **+564,924.2**) N·mm, about the vertical axis through the load node |
| Outputs | Nodal displacement (x, y, z, magnitude) and von Mises stress for each load case (`GPSTRESS`) |

These vectors match the challenge brief's lbf figures to the conversion factor.
They settle the directions the brief left vague: "out" is −x, LC3 is 42° from
vertical (not 30° from horizontal), and the torque axis is +z.

**How designs were put in a common frame.** Units were inferred from bounding-box
volume and rescaled to mm. A user then picked three reference points and the
model was moved to the canonical pose. So the bolt holes and pin sit at the same
coordinates in every design, within picking accuracy.

## 3. File formats

| File | Content |
| --- | --- |
| `<id>.csv` | One row per mesh node: `id, surf, x, y, z`, then for each prefix `ver_`, `hor_`, `dia_`, `tor_`: `xdisp, ydisp, zdisp, magdisp, stress`. `surf` = 1 marks a surface node. Units mm and MPa |
| `<id>.vtk` | Legacy VTK binary unstructured grid (`# vtk DataFile Version 2.0`, "Created by Gmsh"). Node count matches the CSV |
| `<id>.obj` | Wavefront OBJ surface mesh, written by VTK |
| `<id>.fem` | Full OptiStruct/Nastran-format bulk deck (GRID, CTETRA, RBE2, RBE3, SPC, FORCE, MOMENT, MAT1) |
| `<id>.stp` | Cleaned single-solid STEP in mm, canonical pose |
| `all_bracket_metadata.tab` | Comma-separated despite the `.tab` extension. Columns: `id, num_vertices, num_faces, volume, surface_area, average_edge_length, genus`; `max_{ver,hor,dia,tor}_{xdisp,ydisp,zdisp,magdisp,stress}`; `category, num_tets, mass, download_file, link_name, author, author_id, test_split_{0,1,2}` |

**Data quirks to handle:**

- The README's units line gives stress and Young's modulus as "GPa (N/mm²)". N/mm²
  is **MPa**, and the values (median peak around 1,045 MPa) are MPa.
- `mass` in the metadata is in **kg** and uses ρ = 4.47×10⁻⁶ kg/mm³, the paper's
  4.47×10⁻³ g/mm³. The `.fem` material card uses 4.43×10⁻⁹ t/mm³. The two differ by
  0.9%, so recompute mass with our own density rather than mixing sources.
- `volume` is in mm³; `genus` can be negative (for example −80), which points to
  meshes that are not clean manifolds.

## 4. What the metadata shows

We computed these statistics over all 381 designs. Peak stress is the maximum
nodal von Mises stress in each load case; "worst case" is the largest of the four.

| Quantity | Min | Median | Max |
| --- | --- | --- | --- |
| Mass (kg) | 0.198 | 0.651 | 2.219 |
| Volume (mm³) | 44,380 | 145,600 | 496,400 |
| Peak von Mises, LC1 vertical (MPa) | 301 | 1,045 | 14,900 |
| Peak von Mises, LC2 horizontal (MPa) | 235 | 721 | 15,870 |
| Peak von Mises, LC3 diagonal (MPa) | 205 | 607 | 15,280 |
| Peak von Mises, LC4 torsion (MPa) | 71 | 428 | 14,160 |
| Worst-case displacement magnitude (mm) | 0.23 | 1.15 | 32.5 |
| Tetrahedra per design | 82,410 | 363,600 | 3,021,000 |

- **Governing load case:** LC1 vertical is the worst case in **318 of 381** designs,
  then LC2 horizontal (39), LC4 torsion (13) and LC3 diagonal (11). The brief's
  largest force (LC3) is almost never the one that governs.
- **Yield check (131 ksi = 903 MPa):** only **147 of 381** designs keep their
  worst-case peak at or below yield. **40** stay below 602 MPa, which is the SF 1.5
  allowable suggested in the part brief.
- **Lightest designs that pass:**
  - At 903 MPa: design 566, 0.345 kg (block, 865 MPa); design 10, 0.402 kg; design 202, 0.416 kg.
  - At 602 MPa: design 120, 0.673 kg (arch, 536 MPa); designs 428 and 420, 0.872 kg.
- **Suspicious peaks:** **60** designs have worst-case peaks above 2,000 MPa, **10**
  above 5,000 MPa, and **2** above 10,000 MPa. Ti-6Al-4V cannot carry stresses
  like these, so they are almost certainly mesh singularities or distorted
  elements. The authors say as much: stress "could be improved by improving mesh
  quality, using second-order elements, and replacing sharp corners … with small
  fillets."
- **Original part:** the dataset does **not** contain GE's original bracket as a
  labelled baseline. Design 62's file is named `bracketGE-ORIGINAL.igs`, but it
  is an optimised entry (0.476 kg), not the original.

## 5. Licence and attribution

The licensing signals conflict:

| Source | Statement |
| --- | --- |
| Dataverse licence field | CC0 1.0 |
| Dataverse description, README and paper | Open Data Commons **Attribution** License (ODC-By) |
| README and paper, on the CAD files | **"CAD files within the database are from the 'GE jet engine bracket challenge', and licensed for non-commercial use by GrabCAD."** |

Take the most restrictive reading:

- Cite the paper and the dataset DOI.
- Treat the CAD geometry (`.stp`, and the meshes derived from it) as
  **non-commercial**, with attribution to each designer through the README.
- **Do not commit SimJEB files to this public repository.** Fetch them at setup by
  pinned file ID and checksum, the same way `ccx` is handled under
  [D-02](requirements.md).

Recommended citation: E. Whalen, A. Beyene, and C. Mueller, "SimJEB: Simulated Jet
Engine Bracket Dataset," *Computer Graphics Forum* 40(5), SGP 2021,
doi:10.1111/cgf.14353.

## 6. Fit against this project

SimJEB designs are free-form solids, not CadQuery parametric models. So **they
cannot be tasks the agent optimises** under D-04 and D-05. Their value is as
reference data around the pipeline:

| Use | How | Touches |
| --- | --- | --- |
| **Solver cross-check (V3)** | Rebuild design 148's setup in CalculiX: import the `.vtk` mesh, map RBE2 to `*RIGID BODY` and RBE3 to `*DISTRIBUTING COUPLING`, apply the section 2 vectors. Compare nodal displacement against `148.csv`. Displacement is robust to mesh quality, so it is the fair comparison. Stress will differ where the first-order tets are poor. | `REQ-DEL-009`, M1. Adds a real-geometry check beside the two closed-form cases; it complements them rather than replacing them |
| **Boundary conditions for the GE bracket task** | Take section 2 as the definitive frame, load vectors and interface model for any GE-bracket task. That settles the direction ambiguity in the challenge brief | [GE bracket brief §3](ge-jet-engine-bracket.md), `REQ-VER-006` |
| **Contour readability before a pipeline exists** | Render von Mises stress from `148.csv` on `148.obj` with the fixed camera set and locked legend. Use it for M0.5 task 6, and send it through `glc_v5` for task 7. That tests the vision thesis on a real bracket before any solver work | `REQ-OPT-001`, `OD-D`, M0.5 tasks 6–7 |
| **Singularity mutants from real data** | The 10 designs with peaks above 5,000 MPa are ready-made "fake infinite stress" cases. Pair each with a design of similar category and mass whose peak is plausible, as its control | D-12, D-16, `REQ-VER-005` |
| **Wrong-direction mutant** | Flip LC2 to +x, or use LC3 at 30° from horizontal (the challenge's own published error). Detect it by comparing the deck vector with section 2 | D-16, `REQ-VER-006` |
| **Frontier and refusal calibration** | The 381 (mass, worst-case stress) pairs show what hundreds of human designers reached. A mass target below about 0.34 kg at SF 1.0, or below about 0.67 kg at SF 1.5, is beyond every SimJEB design that passes. That is a defensible basis for the unachievable-target fixture, stated as "no design in SimJEB", not as proof | D-15 refusal case, `REQ-OUT-003` |
| **Governing-load-case evidence for D-08** | LC1 governs 83% of designs. If D-08 stays at one load case per task, LC1 vertical is the representative case for a GE bracket task, not LC3 | D-08, [GE bracket brief §7](ge-jet-engine-bracket.md) |

**Mismatches to keep in mind:**

- **Element order.** SimJEB uses first-order `CTETRA`; this project requires
  second-order `C3D10` (D-03). Expect our stresses to be lower and more trustworthy.
  Do not treat SimJEB's stresses as ground truth.
- **Density.** The deck uses 4.43×10⁻⁹ t/mm³ and the metadata mass uses
  4.47×10⁻⁶ kg/mm³ (see section 3). Pick one, with a cited source, in the
  material library.
- **Size.** Design 148 has 640k tets. A second-order remesh would be several million
  DOF, far beyond D-13's 180 s per-solve budget. It works as a one-off validation
  solve, not as an in-loop part.
- **Manufacturability.** SimJEB has no additive-manufacturing or minimum-wall data.
